# 1.介绍
OpenHarmony 系统运行环境中未预装 glibc 库 ，因此无法直接使用默认依赖 glibc 的交叉编译链进行动态编译 ，可采用以下两种方法解决：

1) 静态编译：将依赖的库打包进程序，脱离目标环境的系统库依赖； 

2) 使用 OpenHarmony 原生编译环境：基于鸿蒙官方构建系统编译，适配目标环境的库依赖。  

# 2.修改方法
## 方法一：静态编译
OpenHarmony 目标运行环境缺失 glibc 库，因此使用第三方交叉编译链时需静态编译，具体步骤如下：  

1. 交叉编译工具链路径：

`/home/forlinx/work/openharmony5_1_3568/forlinx-5.1-release/prebuilts/gcc/linux-x86/aarch64/gcc-linaro-7.5.0-2019.12-x86_64_aarch64-linux-gnu/bin/aarch64-linux-gnu-gcc`。

2. 编译源码

编译源码可参考 Linux 系统下的常规编译方式，核心差异在于需采用**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">静态编译</font>**；只需将最终产出的可执行文件放置到鸿蒙环境中使用即可，编译环境无强制要求，调用对应的交叉编译链就行。下文以鸿蒙环境为例，演示如何直接通过交叉编译链编译.c 源码；若采用 Makefile 等脚本方式交叉编译，需在脚本中替换交叉编译链路径，并配置静态编译相关参数。    

将 Linux5.10系统源码下的`app/forlinx/forlinx_cmd/fltest_uarttest/uarttest.c` 复制到 OpenHarmony 源码目录`/home/forlinx/work/openharmony5_1_3568/forlinx-5.1-release/device/board/forlinx/ok3568/tools/uarttest`。

执行静态编译命令`/home/forlinx/work/openharmony5_1_3568/forlinx-5.1-release/prebuilts/gcc/linux-x86/aarch64/gcc-linaro-7.5.0-2019.12-x86_64_aarch64-linux-gnu/bin/aarch64-linux-gnu-gcc uarttest.c -o uarttest -static` 。

3、将生成的uarttest 可执行文件放到目录，`/home/forlinx/work/openharmony5_1_3568/forlinx-5.1-release/device/board/forlinx/ok3568/tools/uarttest/`。

4. 创建uarttest的BUILD.gn文件，`/home/forlinx/work/openharmony5_1_3568/forlinx-5.1-release/device/board/forlinx/ok3568/tools/uarttest/BUILD.gn`。

```plain
import("//build/ohos.gni")

ohos_prebuilt_etc("uart_test"){
    source = "./uarttest"
    module_install_dir = "bin"
    install_images = ["system"]
    part_name = "rockchip_products"
    install_enable = true
}

group("uarttest") {
    deps = [ 
         ":uart_test",
    ]
}
```

修改上一级BUILD.gn，路径`/home/forlinx/work/openharmony5_1_3568/forlinx-5.1-release/device/board/forlinx/ok3568/tools/BUILD.gn`

```plain
import("//build/ohos.gni")

group("tools") {
  deps = [
    "busybox:busybox",
    #"spi:spi",
    "uarttest:uarttest",
  ]
}
```

在BUILG.gn配置编译

首先需要在`<font style="background-color:rgba(0, 0, 0, 0.06);">/home/forlinx/work/openharmony5_1_3568/forlinx-5.1-release/device/board/forlinx/ok3568/tools</font>`路径下创建自己想编译的文件夹，如

创建目录，源码文件

创建配置文件helloxiaohui.c的BUILD.gn，路径：`/home/forlinx/work/openharmony5_1_3568/forlinx-5.1-release/device/board/forlinx/ok3568/tools/hello/BUILD.gn`

```plain
import("//build/ohos.gni")

ohos_executable("helloxiaohui") {
  sources = [ "helloxiaohui.c" ]

  include_dirs = []   # 如果有头文件路径可加在这里

  deps = []           # 如果需要依赖其他模块，可以写在这里

  install_enable = true  # 启用安装
  part_name = "rockchip_products"          # 要与 ohos.build 文件保持一致，此处是device/board/forlinx/ok3568/ohos.build

  install_images = [ "system" ]   # 指定安装到 system 分区
  module_install_dir = "bin"      # 安装到 /system/bin
  cflags = [
    "-Wno-error=unused-variable",  # helloxiaohui.c代码中有未使用的变量定义，编译时会报错，添加选项，代码中定义的变量如果未使用也不报错
    "-Wno-error=implicit-fallthrough",
  ]
}
```

修改上一级BUILD.gn，路径`/home/forlinx/work/openharmony5_1_3568/forlinx-5.1-release/device/board/forlinx/ok3568/tools/BUILD.gn`

```plain
import("//build/ohos.gni")

group("tools") {
  deps = [
    "busybox:busybox",
    #"spi:spi",
    "uarttest:uarttest",
    "hello:helloxiaohui",
  ]
}
```

# 3.编译
进行全编译，不用删除out目录

`forlinx@ubuntu:~/openharmony-v5.1-release $<font style="color:rgba(9,49,250,1);">./build.sh -p ok3568 --ccache</font>`

这样应用就会直接放到文件系统，打包到镜像当中。

效果：

<img src="https://cdn.nlark.com/yuque/0/2025/png/49293577/1759026585210-6c0d8d13-e190-439b-9c12-d5664ad22ba3.png?x-oss-process=image%2Fformat%2Cwebp" width="892" title="" crop="0,0,1,1" id="zY2Vv" class="ne-image">

但是全编译时间比较长，不便于验证，可以采用单编译应用的方式，用来测试

`./build.sh -p ok3568 --ccache --build-target "目标路径"`

比如单独编译上面方法二添加的helloxiaohui

`forlinx@ubuntu20:~/work/openharmony5_1_3568/forlinx-5.1-release $<font style="color:rgba(9,49,250,1);">./build.sh -p ok3568 --ccache --build-target "device/board/forlinx/ok3568/tools/hello:helloxiaohui"</font>`
