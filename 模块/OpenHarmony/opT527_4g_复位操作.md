# T527 OpenHarmony 5.0 外挂 4G 模块复位操作（hdc shell）

**平台**：T527 OpenHarmony 5.0（`sun55iw3`，kernel 5.10.210）
**模组**：Quectel EC200A（USB ID `2c7c:6005`）
**连接方式**：`hdc` → 板卡 `/bin/sh`

***

## 一、确认模块与串口映射

```bash
hdc list targets                       # 确认板卡已连接
hdc shell "uname -a"                   # 确认平台/内核
```

在 `hdc shell` 中查看模组识别的 USB 设备与串口：

```bash
# 列出 4G 模组（Quectel 2c7c）
for d in /sys/bus/usb/devices/*/; do
  v=$(cat $d/idVendor 2>/dev/null); p=$(cat $d/idProduct 2>/dev/null)
  [ -n "$v" ] && echo "$d idVendor=$v idProduct=$p"
done

# 查看 ttyUSB 归属（应全部指向 3-1.3 模组）
ls -l /sys/class/tty/ttyUSB*
```

EC200A 在 QMI 模式下的接口与串口对应关系：

| 接口 | 设备节点 | 用途 |
|------|----------|------|
| 3-1.3:1.2 | `/dev/ttyUSB0` | DM 诊断口 |
| 3-1.3:1.3 | `/dev/ttyUSB1` | GPS/NMEA |
| 3-1.3:1.4 | `/dev/ttyUSB2` | **AT 命令口** |
| 3-1.3:1.6 | `/dev/ttyUSB3` | AT/PPP |

> 本板实测模组为 **EC200A**（`ATI` 返回），与文档 `opT527_4g.md` 中的 EC20 同属移远 EC20/EC200 系列，AT 口均为 `/dev/ttyUSB2`。

***

## 二、测试 AT 口

板卡自带 `/bin/microcom`（busybox），可用管道非交互发送 AT：

```bash
printf 'AT\r' | busybox microcom -t 2000 -s 115200 /dev/ttyUSB2
# 期望输出：OK
```

***

## 三、软复位模块（推荐）

向 AT 口发送 `AT+CFUN=1,1`，模块会保存配置后软复位（重启基带）：

```bash
printf 'AT+CFUN=1,1\r' | busybox microcom -t 3000 -s 115200 /dev/ttyUSB2
```

说明：该命令通常无回显或仅回 `OK`，随后模组重启，USB 接口会重新枚举，约需 10~20 秒。

***

## 四、验证复位结果

```bash
sleep 20
hdc shell "ls /dev/ttyUSB*; ls /sys/bus/usb/devices/ | grep 3-1.3"
hdc shell "printf 'ATI\r' | busybox microcom -t 2000 -s 115200 /dev/ttyUSB2"
```

实测复位后输出：

```
Quectel
EC200A
Revision: EC200ACNGAR01A05M16

OK
```

`/dev/ttyUSB0-3` 与 USB 设备 `3-1.3` 均已恢复即复位成功。

***

## 五、重新拨号上网

复位后 `quectel-CM` 拨号进程不会自动恢复，需手动重启：

```bash
# 确认 QMI 控制通道存在
ls /dev/cdc-wdm0

# 手动启动拨号
quectel-CM -d /dev/cdc-wdm0 &
# 或指定 APN
quectel-CM -d /dev/cdc-wdm0 -s internet &
```

检查结果：

```bash
ifconfig wwan0
ping -c 3 baidu.com
```

***

## 六、硬复位（AT 无响应时）

若模组死机、AT 口无任何回显，改用 GPIO 断电复位。

设备树中 4G 电源控制节点（见 `opT527_4g.md`）：

```dts
pwren_4g {
    compatible = "regulator-fixed";
    regulator-name = "pwren_4g";
    gpio = <&pio PB 13 GPIO_ACTIVE_HIGH>;
    regulator-always-on;
    enable-active-high;
    status = "okay";
};
```

sysfs 方式（`gpiochip0` base=0，PB13 = 1*32+13 = 45）：

```bash
echo 45 > /sys/class/gpio/export
echo out > /sys/class/gpio/gpio45/direction

echo 0 > /sys/class/gpio/gpio45/value   # 断电
sleep 3
echo 1 > /sys/class/gpio/gpio45/value   # 上电，模组重新枚举

echo 45 > /sys/class/gpio/unexport
```

也可用 USB 重新枚举（仅复位 USB 接口，不断电）：

```bash
echo 3-1.3 > /sys/bus/usb/drivers/usb/unbind
sleep 2
echo 3-1.3 > /sys/bus/usb/drivers/usb/bind
```

> 注意：`pwren_4g` 已在设备树标记 `regulator-always-on`，手工 sysfs 导出同号 GPIO 前请确认该脚未被 regulator 框架占用，避免冲突。

***

## 七、复位方法对照

| 方法 | 命令 | 适用场景 | 影响 |
|------|------|----------|------|
| AT 软复位 | `AT+CFUN=1,1` | 常规重启基带（推荐） | 模组重启，USB 重新枚举 |
| USB 重枚举 | sysfs `unbind`/`bind` | 仅 USB 挂死 | 接口重新绑定 |
| GPIO 硬复位 | 拉低/拉高 PB13 | 模组死机、AT 无响应 | 模组彻底断电重启 |

**相关文档**：`opT527_4g.md`（EC20 适配全过程）、`opT527_ch340.md`（确认 CH340 使用 `/dev/ttyCH341USBx`，不与 4G 的 `/dev/ttyUSBx` 冲突）。
