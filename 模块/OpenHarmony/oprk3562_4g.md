## 一、适配 USB 驱动
EG800K 系列模组支持 ECM、RNDIS、USB 转串口 option 等驱动，本文选择 **ECM 驱动** 适配。

### 1. USB 驱动配置项
| USB 驱动 | 配置项 | 源文件 |
| --- | --- | --- |
| ACM | CONFIG_USB_ACM | [KERNEL]/drivers/net/usb/cdc-acm.c |
| ECM | CONFIG_USB_NET_DRIVERS=y<br>CONFIG_USB_USBNET=y<br>CONFIG_USB_NET_CDCETHER=y | [KERNEL]/drivers/net/usb/cdc_ether.c |
| RNDIS | CONFIG_USB_NET_DRIVERS<br>CONFIG_USB_USBNET<br>CONFIG_USB_NET_RNDIS_HOST | [KERNEL]/drivers/net/usb/rndis_host.c |
| NCM | CONFIG_USB_NET_DRIVERS<br>CONFIG_USB_USBNET<br>CONFIG_USB_NET_CDC_NCM | [KERNEL]/drivers/net/usb/cdc_ncm.c |
| MBIM | CONFIG_USB_NET_DRIVERS<br>CONFIG_USB_USBNET<br>CONFIG_USB_NET_CDC_MBIM | [KERNEL]/drivers/net/usb/cdc_mbim.c |

### 2. 内核配置修改
在 `rk3562_standard_defconfig` 中添加：
```ini
CONFIG_USB_NET_DRIVERS=y
CONFIG_USB_USBNET=y
CONFIG_USB_NET_CDCETHER=y
```

## 二、移植 quectel-CM 拨号工具
### 1. 获取源码
向移远客服获取：`Quectel_QConnectManager_Linux_V1.6` 源码。

### 2. 核心源文件
```
QmiWwanCM.c
GobiNetCM.c
main.c
QCQMUX.c
QMIThread.c
util.c
qmap_bridge_mode.c
mbim-cm.c
device.c
atc.c
atchannel.c
at_tok.c
udhcpc.c
```

### 3. 编写 BUILD.gn
路径：`third_party/quectel/quectel-cm/BUILD.gn`
```gn
import("//build/ohos.gni")

group("quectel-cm-group") {
  deps = [
    ":quectel-CM"
  ]
}

ohos_executable("quectel-CM") {
  sources = [
    "QmiWwanCM.c",
    "GobiNetCM.c",
    "main.c",
    "QCQMUX.c",
    "QMIThread.c",
    "util.c",
    "qmap_bridge_mode.c",
    "mbim-cm.c",
    "device.c",
    "atc.c",
    "atchannel.c",
    "at_tok.c",
    "udhcpc.c"
  ]

  defines = [
    "USE_OHOS"
  ]

  include_dirs = [
    "//third_party/quectel/quectel-cm",
  ]

  install_enable = true
  part_name = "ril_adapter"
  subsystem_name = "telephony"
  install_images = [
    "system",
    "updater"
  ]

  cflags = [
    "-Wall",
    "-Wno-unused-function",
    "-Wno-unused-variable",
    "-Wno-missing-braces"
  ]
}
```

### 4. 加入编译依赖
修改 `base/telephony/ril_adapter/bundle.json`，添加：
```json
"//third_party/quectel/quectel-cm:quectel-cm-group"
```

### 5. 编译命令
```bash
./build.sh --product-name rk3562 --ccache
```
编译后产物路径：`out/rk3562/packages/phone/system/bin/quectel-CM`

## 三、自启动 quectel-CM 拨号工具
修改 `device/board/hihope/rk3562/cfg/init.rk3562.cfg`：

### 1. 添加服务配置
```json
{
  "name": "quectel-cm",
  "path": ["/system/bin/quectel-CM"],
  "secon": "u:r:su:s0",
  "uid": "root",
  "gid": ["root", "system"]
}
```

### 2. 添加启动时序
```json
"jobs": [
  {
    "name": "post-fs-data",
    "cmds": [
      ...,
      "wait /dev/ttyUSB1",
      "start quectel-cm"
    ]
  }
]
```

### 3. secon 说明
- 格式：`u:r:domain:s0`
- 自定义 `quectel-cm` 域因无 SELinux 策略会启动失败，改用系统预定义的 `su` 域（`u:r:su:s0`）可正常启动。

## 四、遇到的问题及解决
### 问题一：缺少 busybox 工具
- 现象：`busybox: inaccessible or not found`
- 解决：将 busybox 预编译内置到系统。
  路径：`device/board/hihope/rk3562/modem/BUILD.gn`
```gn
ohos_prebuilt_executable("busybox") {
  source = "busybox/busybox"
  install_enable = true
  part_name = "rockchip_products"
}
```

### 问题二：缺少 default.script 文件
- 解决：
  1. 从 QConnectManager 工具包获取并修改：`/sbin/route` → `busybox route`，`/sbin/ifconfig` → `ifconfig`
  2. 在 `build/ohos/images/mkimage/dac.txt` 添加权限：
```
system/etc/udhcpc/*,0777,0,2000,0
```

### 问题三：quectel-cm 与 /dev/ttyUSB1 时序问题
- 现象：进程启动早于 USB 设备枚举，立即退出
- 解决：启动前添加 `wait /dev/ttyUSB1`

### 问题四：DNS 解析问题
- 解决：
  1. 修改 `build/config/components/musl/BUILD.gn`：
```ini
OHOS_DNS_PROXY_BY_NETSYS=0
OHOS_FWMARK_CLIENT_BY_NETSYS=0
```
  2. 修复 `third_party/musl/src/network/resolvconf.c`：
```c
// 原：#ifdef OHOS_FWMARK_CLIENT_BY_NETSYS
// 改：#if OHOS_FWMARK_CLIENT_BY_NETSYS
```
