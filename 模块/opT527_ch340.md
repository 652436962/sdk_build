# T527 OpenHarmony 5.0 适配 CH340 USB 转串口驱动（飞凌 OKT527-C）

**芯片型号**：CH340/CH341 USB 转串口  
**适配平台**：T527 OpenHarmony 5.0  
**内核版本**：Linux 5.10  
**驱动来源**：南京沁恒微电子（WCH）官方驱动 V1.8，替换内核 in-tree 版本  

---

## 一、内核配置修改

**文件**：`device/soc/allwinner/t527/patches/config/t527_standard_defconfig`

```ini
CONFIG_USB_SERIAL_CH341=y
```

> 此驱动为独立 USB 驱动，不依赖 `CONFIG_USB_SERIAL` 框架。CH340 与 CH341 共用同一驱动。

---

## 二、替换内核驱动源码（使设备节点为 ttyCH341USB）

官方 WCH 驱动自带独立 tty_driver，设备节点为 `/dev/ttyCH341USBx`，避免与 4G 模块的 `/dev/ttyUSBx` 冲突。

### 2.1 修改文件清单

| 文件 | 操作 |
| ---- | ---- |
| `kernel/linux/linux-5.10/drivers/usb/serial/ch341.c` | 用 `模块/ch340/CH341SER_LINUX/driver/ch341.c` 替换 |
| `kernel/linux/linux-5.10/drivers/usb/serial/ch341.h` | 新增，从 `模块/ch340/CH341SER_LINUX/driver/ch341.h` 复制 |
| `kernel/linux/linux-5.10/drivers/usb/serial/Kconfig` | 将 `USB_SERIAL_CH341` 移出 `if USB_SERIAL` 块，改为独立配置项 |
| `kernel/linux/linux-5.10/drivers/usb/Makefile` | 添加 `obj-$(CONFIG_USB_SERIAL_CH341) += serial/` |

### 2.2 Kconfig 修改

将 `USB_SERIAL_CH341` 从 `if USB_SERIAL` 块中移出，放置在 `endif # USB_SERIAL` 之后：

```kconfig
endif # USB_SERIAL

config USB_SERIAL_CH341
	tristate "USB Winchiphead CH341 Single Port Serial Driver (standalone)"
	depends on TTY
	help
	  Say Y here if you want to use a Winchiphead CH341 single port
	  USB to serial adapter. This driver operates independently from
	  the USB Serial Converter framework.

	  Device node: /dev/ttyCH341USBx

	  To compile this driver as a module, choose M here: the
	  module will be called ch341.
```

### 2.3 drivers/usb/Makefile 修改

在 `obj-$(CONFIG_USB_SERIAL) += serial/` 后添加一行：

```makefile
obj-$(CONFIG_USB_SERIAL_CH341)	+= serial/
```

确保 `CONFIG_USB_SERIAL=n` 时 `serial/` 目录仍能进入编译 ch341。

## 三、编译

```bash
# 1. 进入容器
docker start t527_openharmony
docker exec -it t527_openharmony /bin/bash

# 2. 提交修改（构建会 clone 新代码，不 commit 会丢失）
# 注意：kernel/linux/linux-5.10 是 git submodule，需先在子模块内提交
cd /home/openharmony/forlinx-5.0-release

cd kernel/linux/linux-5.10
git add drivers/usb/serial/ch341.c
git add drivers/usb/serial/ch341.h
git add drivers/usb/serial/Kconfig
git add drivers/usb/Makefile
git commit -m "feat: replace CH341 driver with WCH standalone version (ttyCH341USB)"
cd /home/openharmony/forlinx-5.0-release

git add kernel/linux/linux-5.10
git add device/soc/allwinner/t527/patches/config/t527_standard_defconfig
git commit -m "feat: replace CH341 driver with WCH standalone version (ttyCH341USB)"

# 3. 编译
./build.sh --product-name okt527 --ccache
```

## 四、验证

```bash
# 插入 CH340 后，在板子串口执行

# 1. 查看内核日志
dmesg | tail
# 预期输出：
# ttyCH341USB0: ch341 USB device

# 2. 查看串口设备
ls /dev/ttyCH341USB*
# 预期输出：/dev/ttyCH341USB0

# 3. 确认不与 4G 模块冲突
ls /dev/ttyUSB*       # 4G 模块设备
ls /dev/ttyCH341USB*  # CH340 设备
```

## 五、常用串口操作

```bash
# 查看串口参数
stty -F /dev/ttyCH341USB0

# 设置波特率 115200
stty -F /dev/ttyCH341USB0 115200

# 读取串口数据
cat /dev/ttyCH341USB0

# 发送数据
echo "test" > /dev/ttyCH341USB0
```

## 六、常见问题

### 问题一：无 `/dev/ttyCH341USB0` 节点

- **原因一**：`CONFIG_USB_SERIAL_CH341` 未开启
- **解决**：按本文第一节修改并重新编译

- **原因二**：USB 口供电不足
- **解决**：更换 USB 口或使用带外部供电的 HUB

### 问题二：有设备节点但无法通信

- **原因**：波特率不匹配
- **解决**：`stty -F /dev/ttyCH341USB0 115200` 设置正确波特率

### 问题三：编译后修改未生效

- **原因**：T527 OpenHarmony 构建会 clone 新内核源码，未 commit 的修改会丢失
- **解决**：在容器内 `git commit` 后再编译

### 问题四：`git add kernel/...` 报错 "is in submodule"

- **原因**：`kernel/linux/linux-5.10` 是 git submodule，不能从父仓库直接 add 其内部文件
- **解决**：先 `cd kernel/linux/linux-5.10` 在子模块内提交内核改动，再回到父仓库 `git add kernel/linux/linux-5.10` 更新子模块引用

### 问题五：编译报错找不到 `usb_serial_*` 符号

- **原因**：使用了旧的 in-tree ch341.c（依赖 usb_serial 框架）
- **解决**：确认已替换为 WCH 官方独立驱动，且 Kconfig 已移出 `if USB_SERIAL` 块

## 七、WCH 驱动 vs 内核 in-tree 驱动对比

| 特性 | 内核 in-tree (原版) | WCH 官方驱动 (当前) |
| ---- | ------------------- | ------------------- |
| 框架依赖 | usb_serial 框架（必须 `CONFIG_USB_SERIAL=y`） | 独立 usb_driver，不依赖 usb_serial |
| 设备节点 | `/dev/ttyUSBx` | `/dev/ttyCH341USBx` |
| 厂商 | 社区维护 | 沁恒原厂（V1.8 2024.08） |
| 批量传输 | 单 URB | 多 URB（4 个读 URB，2 个写 URB） |
| 流控 | 基础支持 | 硬件流控、DTR/RTS 完整支持 |
| 波特率 | 46 ~ 3000000 | 全范围支持 |
