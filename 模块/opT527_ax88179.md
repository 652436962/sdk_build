# T527 OpenHarmony 5.0 适配 AX88179 USB 千兆网卡（飞凌 OKT527-C）

**芯片型号**：ASIX AX88179/178A USB 3.0/2.0 to Gigabit Ethernet  
**适配平台**：T527 OpenHarmony 5.0  
**内核版本**：Linux 5.10  

---

## 一、问题现象

插入 AX88179 USB 网卡后，`ifconfig -a` 无设备节点，`dmesg` 无驱动加载日志。

**根本原因**：`CONFIG_USB_USBNET`（USB 网络驱动框架）未使能，导致 `CONFIG_USB_NET_AX88179_178A` 被 kconfig **静默丢弃**，最终内核未编译 AX88179 驱动。

---

## 二、内核配置修改

**文件**：`device/soc/allwinner/t527/patches/config/t527_standard_defconfig`

```ini
# ASIX AX88179/178A USB 3.0/2.0 to Gigabit Ethernet driver
CONFIG_USB_USBNET=y
CONFIG_USB_NET_AX88179_178A=y
```

> `CONFIG_USB_NET` **不是有效的内核配置符号**，必须用 `CONFIG_USB_USBNET`（Multi-purpose USB Networking Framework）。

---

## 三、驱动依赖关系

AX88179 驱动在内核 Kconfig 中的依赖链：

```
CONFIG_USB_USBNET=y                          ← USB 网络框架（必须）
  └── CONFIG_USB_NET_DRIVERS=y               ← 自动选中
      └── CONFIG_USB_NET_AX88179_178A=y      ← AX88179 驱动
```

如果 `CONFIG_USB_USBNET` 未开启，`AX88179_178A` 即使写了 `=y` 也会被 kconfig 静默丢弃。

---

## 四、编译

```bash
# 1. 进入容器
docker start t527_openharmony
docker exec -it t527_openharmony /bin/bash

# 2. 提交修改（构建会 clone 新代码，不 commit 会丢失）
cd /home/openharmony/forlinx-5.0-release
git add device/soc/allwinner/t527/patches/config/t527_standard_defconfig
git commit -m "fix: enable CONFIG_USB_USBNET for AX88179 driver"

# 3. 编译
./build.sh --product-name okt527 --ccache
```

## 五、验证

```bash
# 插入网卡后，在板子串口执行

# 1. 查看 USB 设备是否识别
cat /sys/kernel/debug/usb/devices | grep -A5 "Ax88179\|ASIX"

# 2. 查看内核日志
dmesg | grep -i "ax88179\|asix"

# 3. 查看网络接口
ifconfig -a
```

**预期输出**：
```
ax88179_178a 1-1:1.0 eth1: register 'ax88179' at usb-sunxi-ehci-1, ASIX AX88179 USB 3.0 Gigabit Ethernet
```

`ifconfig -a` 可看到 `eth1`（或有线网卡之后的序号）。

## 六、常见问题

### 问题一：已配置驱动但编译后仍不生效

- **原因**：T527 OpenHarmony 构建会 clone 新内核源码，本地未 commit 的修改会被丢弃
- **解决**：在容器内 `git commit` 后再编译

### 问题二：写的是 `CONFIG_USB_NET=y` 但不生效

- **原因**：`CONFIG_USB_NET` 不是有效内核符号，正确的框架符号是 `CONFIG_USB_USBNET`
- **解决**：改为 `CONFIG_USB_USBNET=y`

### 问题三：`lsusb` 看不到设备

- **原因**：USB 口供电不足或 USB 控制器未使能
- **解决**：检查硬件供电，确认 USB 口在 Host 模式

### 问题四：能识别但无法获取 IP

- **原因**：缺少 DHCP 客户端
- **解决**：
```bash
udhcpc -i eth1
```
