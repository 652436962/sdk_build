# RK3568 MCP23S17 SPI GPIO 扩展芯片配置

## 1. 设备树配置

```dts
&spi0 {
    pinctrl-names = "default", "high_speed";
    pinctrl-0 = <&spi0m1_cs0 &spi0m1_pins>;
    pinctrl-1 = <&spi0m1_cs0 &spi0m1_pins_hs>;
    status = "okay";

    mcp23s17@0 {
        compatible = "microchip,mcp23s17";
        gpio-controller;
        #gpio-cells = <2>;
        microchip,spi-present-mask = <0x01>;
        reg = <0>;
        spi-max-frequency = <1000000>;
    };
};
```

> **注意**：如果 SPI 总线还连接了其他设备（如 spidev），需要将对应节点的 `reg` 号错开，避免冲突。

## 2. 核心排查清单

### 2.1 确认驱动已编进内核

运行以下命令检查驱动模块是否存在或编译进内核：

```bash
zcat /proc/config.gz | grep MCP23
```

应该至少看到：

```
CONFIG_GPIO_MCP23S08=y
```

或：

```
CONFIG_GPIO_MCP23S08=m
```

如果没有，说明驱动未启用，必须启用并重新编译内核：

```bash
make menuconfig
```

路径通常为：

```
Device Drivers --->
    Pin controllers --->
        <*> Microchip MCP23S08 I/O expander
```

> **注意**：该驱动同时支持 `mcp23s08` 和 `mcp23s17`，log 中名称会以 `mcp23s08` 表示。

### 2.2 确认 SPI probe 是否注册成功

查看总线下注册的设备：

```bash
ls /sys/bus/spi/devices/
```

你应该能看到类似 `spi0.0`。

然后再看是否绑定了驱动：

```bash
ls -l /sys/bus/spi/devices/spi0.0/driver
```

如果没有绑定任何驱动（目录不存在或为空），说明匹配失败，可能是 `compatible` 不对。

### 2.3 确认是否导出了 GPIO 节点

查看是否生成了新的 GPIO 控制器：

```bash
ls /sys/class/gpio/
```

或更准确方式查找 mcp23s17 对应的 GPIO 控制器：

```bash
grep . /sys/class/gpio/gpiochip*/label
```

如果成功加载驱动，应该能看到类似输出：

```
/sys/class/gpio/gpiochip496/label:mcp23s17
```

这表示 `/dev/gpiochipX` 已注册成功。

### 2.4 控制 IO 测试（GPIO 已注册后）

以第一个 GPIO 为例，手动测试：

```bash
echo 496 > /sys/class/gpio/export
echo out > /sys/class/gpio/gpio496/direction
echo 1 > /sys/class/gpio/gpio496/value
echo 496 > /sys/class/gpio/unexport
```

看电平是否拉高。

> **提示**：GPIO 起始号因平台不同而异，以实际 `/sys/class/gpio/gpiochip*/label` 为准。

## 3. GPIO 控制脚本 (gpio.sh)

使用示例：

```bash
root@OK3568-buildroot:~# ./gpio.sh 496 0
root@OK3568-buildroot:~# ./gpio.sh 496 1
```

脚本内容：

```bash
#!/bin/bash

# 检查参数是否正确
if [ $# -ne 2 ]; then
    echo "用法: $0 <引脚号> <电平值(0|1)>"
    echo "示例: $0 101 1  # 设置GPIO101为高电平"
    exit 1
fi

GPIO=$1
VALUE=$2

# 检查电平值是否合法
if [ "$VALUE" != "0" ] && [ "$VALUE" != "1" ]; then
    echo "错误: 电平值必须是0或1"
    exit 1
fi

# 检查GPIO是否已导出，若已导出则先释放
if [ -d "/sys/class/gpio/gpio$GPIO" ]; then
    echo $GPIO > /sys/class/gpio/unexport 2>/dev/null
    sleep 0.1  # 等待释放完成
fi

# 导出GPIO
echo "导出GPIO$GPIO..."
if ! echo $GPIO > /sys/class/gpio/export 2>/dev/null; then
    echo "错误: 无法导出GPIO$GPIO，可能被占用或不存在"
    exit 1
fi

# 等待sysfs节点创建
sleep 0.1
if [ ! -d "/sys/class/gpio/gpio$GPIO" ]; then
    echo "错误: GPIO$GPIO节点创建失败"
    exit 1
fi

# 设置为输出模式
echo "设置GPIO$GPIO为输出模式..."
if ! echo out > /sys/class/gpio/gpio$GPIO/direction 2>/dev/null; then
    echo "错误: 无法设置GPIO$GPIO为输出模式"
    # 清理资源
    echo $GPIO > /sys/class/gpio/unexport 2>/dev/null
    exit 1
fi

# 设置电平值
echo "设置GPIO$GPIO为$VALUE电平..."
if ! echo $VALUE > /sys/class/gpio/gpio$GPIO/value 2>/dev/null; then
    echo "错误: 无法设置GPIO$GPIO为$VALUE电平"
    # 清理资源
    echo $GPIO > /sys/class/gpio/unexport 2>/dev/null
    exit 1
fi

# 短暂延迟确保电平稳定
sleep 0.1

# 自动释放GPIO
echo "释放GPIO$GPIO..."
echo $GPIO > /sys/class/gpio/unexport 2>/dev/null

echo "操作完成"
```

## 4. GPIO 引脚映射表

MCP23S17 有 16 个 GPIO 引脚，分为 GPA（8 个：GPA0 ~ GPA7）和 GPB（8 个：GPB0 ~ GPB7）两组。以基地址 496 为例，对应关系如下：

| 组 | 引脚 | GPIO 编号 |
|----|------|-----------|
| GPA | GPA0 | 496 |
| GPA | GPA1 | 497 |
| GPA | GPA2 | 498 |
| GPA | GPA3 | 499 |
| GPA | GPA4 | 500 |
| GPA | GPA5 | 501 |
| GPA | GPA6 | 502 |
| GPA | GPA7 | 503 |
| GPB | GPB0 | 504 |
| GPB | GPB1 | 505 |
| GPB | GPB2 | 506 |
| GPB | GPB3 | 507 |
| GPB | GPB4 | 508 |
| GPB | GPB5 | 509 |
| GPB | GPB6 | 510 |
| GPB | GPB7 | 511 |

**使用示例** — 控制 GPB0（编号 504）输出高电平：

```bash
# 导出GPB0引脚
echo 504 > /sys/class/gpio/export

# 设置为输出模式
echo "out" > /sys/class/gpio/gpio504/direction

# 输出高电平
echo 1 > /sys/class/gpio/gpio504/value

# 输出低电平
echo 0 > /sys/class/gpio/gpio504/value
```

如果需要使用其他引脚，只需将上述命令中的编号替换为对应引脚的编号即可。

如果需要读取输入状态，将方向设置为 `"in"` 后使用 `cat` 命令读取 `value` 文件：

```bash
echo "in" > /sys/class/gpio/gpio504/direction
cat /sys/class/gpio/gpio504/value
```
