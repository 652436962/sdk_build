# AP6275S 集成计划

> 目标：在 RK3562 / TL3562-EVM（GY-100D，Ubuntu 20.04，内核 5.10.209-rt89）上，
> 用 Broadcom AP6275S（BCM43752，正基，"TF 卡形态"测试板）替换原 WiFi 模组，跑通 SDIO WiFi。

## 一、前置事实（已核对）

| 项 | 结论 |
|----|------|
| 驱动支持 | SDK 内核 `rkwifi/bcmdhd` 已含 `{BCM43752_CHIP_ID, 2, "bcm43752a2_ag", "ap6275s"}` |
| 内核配置 | `BCMDHD=y / AP6XXX=m / BCMDHD_SDIO=y`，FW/NVRAM 路径 `/vendor/etc/firmware/` |
| 固件 | SDK 树内没有，来自 `external/rkwifibt/firmware/broadcom/AP6275S/wifi/`（已拷到本目录 `firmware/`） |
| 驱动版本 | 原 `101.10.361.18 (2022)` → 升级为 `101.10.361.36 (2023)` |
| 模组接入方式 | AP6275S 做成 **TF 卡形态**，插主机 **TF 卡座** → 走 `sdmmc0`（`mmc1`） |
| 关键电气（原理图） | **SDIO 是 1.8V 信令**；`WL_REG_ON` 由 R113 常接 1.8V（默认使能）；`WL_HOST_WAKE` 悬空 |

## 二、改动清单（最终版）

1. **驱动替换**：`.../rkwifi/bcmdhd` ← `bcmdhd.101.10.591.x.rk`（原版备份 `bcmdhd.orig`）
2. **内核配置**：`CONFIG_AP6XXX=y`（bcmdhd **内建**）；中断改 **in-band**
   （`rkwifi/bcmdhd/Makefile` 注释 `CONFIG_BCMDHD_OOB := y` → 走 `-DSDIO_ISR_THREAD`）
3. **设备树** `tl3562-evm-sdio-wifi.dts`：
   - `&vccio_sd`：`min=max=1800000`（**钉死 1.8V**，该 regulator 仅 sdmmc0 用）→ 解决 1.8V 信令
   - `&sdmmc0`：SDIO、`no-sd`、`bus-width=4`、`cap-sdio-irq`、`keep-power-in-suspend`、`non-removable`、
     `max-frequency=50000000`、`vqmmc-supply=<&vccio_sd>`；**不加 `mmc-pwrseq`**
   - `&sdio_pwrseq { status="disabled"; }`
   - `&{/wireless-wlan}`：`status="okay"`、`wifi_chip_type="ap6275s"`、**删除 `WIFI,host_wake_irq`/pinctrl**（in-band）
   - `&sdmmc1 { status="disabled"; }`
4. **固件**：`fw_bcm43752a2_ag.bin` / `nvram_ap6275s.txt` / `clm_bcm43752a2_ag.blob` → rootfs `/vendor/etc/firmware/`
   （`build.sh updateimg` 不自动应用 overlay，本次是**挂载 `rootfs.img` 直接注入**）
5. **编译烧录**：`./build.sh kernel` → `RK_ROOTFS_OVERLAY=1 ./build.sh updateimg`

## 三、验证命令

```
dmesg | grep -iE "dhd|bcmdhd"   # 期望: F1 signature OK chip:0xaae8 → Final fw_path → Firmware up
ls /sys/bus/sdio/devices/       # 期望: 0000:... (0x02d0:0xaae8)
cat /sys/kernel/debug/mmc1/ios  # 期望: signal voltage 1.80 V
iw dev                          # wlan0
iw dev wlan0 scan | head
```

## 四、实测进展（2026-10-15）

| 轮次 | 改动 | 结果 |
|------|------|------|
| 1 | 驱动替换 + `mmc-pwrseq=<&sdio_pwrseq>`(pca9555 IO1_4) | `mmc1: error -110`（SDIO 无应答） |
| 2 | 去掉 pwrseq | 仍 `-110` |
| 3 | 最小可用（WL_REG_ON 常高 / WL_HOST_WAKE 悬空 / **in-band** 中断） | 仍 `-110` |
| 4 | 加回 `sd-uhs-sdr104` | 仍 `-110`（1.8V 切换要等卡应答，死锁） |
| 5 | **`vccio_sd` 钉死 1.8V** | 仍 `-110`，但 `ios` 已确认 `signal voltage 1.80 V` |

**结论**：软件侧全部就位（1.8V 信令已生效、无 pwrseq、in-band、`ap6275s`、bcmdhd 内建、固件在 rootfs），
**模组对 SDIO 命令(CMD5)始终无响应**（`mmc1: error -110`）→ 属**硬件/供电/连接**层面。
同座普通 TF 卡可正常识别（座子电气正常）。
